## KONTEKS DAN TUJUAN

Aplikasi Monefyi harus menyatukan 3 aspek yang selama ini terpisah:

1. **Janji di Landing Page** — apa yang dijual ke calon user
2. **Fitur di Aplikasi** — apa yang benar-benar user dapat
3. **In-App Marketing** — bagaimana user diarahkan ke value lebih tinggi

Ketiga aspek ini WAJIB sinkron. User yang datang dari landing page harus mendapatkan tepat apa yang dijanjikan, dan aplikasi harus proaktif membantu user upgrade sesuai kebutuhan mereka — tanpa menjadi mengganggu.

Super Admin memegang kontrol penuh atas semua behavior marketing di dalam aplikasi.

---

## PRINSIP DASAR YANG WAJIB DIPATUHI

### 1. Zero Broken Promise
Setiap fitur yang dijanjikan di landing page HARUS ada di aplikasi.
Jika belum ada, marketing message harus di-adjust atau fitur di-mark "coming soon" dengan timeline jelas.

### 2. Contextual, Not Interruptive
In-app offer muncul saat user butuh, bukan saat user sedang fokus.
Frequency dibatasi, dismiss selalu tersedia, tidak block user flow.

### 3. Value First, Offer Second
Setiap offer harus menjelaskan value dulu, harga belakangan.
"Kamu akan dapat X yang bantu Y" bukan "Beli sekarang Rp Z".

### 4. Respect User Decision
Kalau user dismiss/skip offer, hormati minimal 7 hari sebelum tampil lagi.
Kalau user "not interested" 3x, jangan tampilkan lagi minimal 30 hari.

### 5. Super Admin Control Everything
Semua behavior (timing, frequency, content, targeting) harus bisa diatur dari admin panel.
Tidak ada hardcoded marketing rules.

## BAGIAN 2: IN-APP MARKETING ENGINE

### TASK 2.1: Architecture Marketing Engine

Bangun sistem yang bisa:
1. Detect user context (plan, usage, behavior)
2. Determine offer eligibility
3. Show offer dengan timing dan format yang tepat
4. Track interaction dan outcome
5. Respect user preferences dan history

```

- id
- campaign_id
- offer_type (upgrade/couple_activation/pro_upgrade/reactivation/etc)

- content_json (headline, body, cta, image, etc)

#### Context Detection

Sistem harus track:
- User plan (trial/basic/pro/lifetime)
- Days since registration
- Days since last login
- Feature usage (mana yang sering dipakai)
- Financial status (safe/warning/danger)
- Subscription status
- Household status (solo/couple_active/couple_inactive)
- Purchase history
- Previous offer interactions

#### Trigger Points

Offer bisa muncul di trigger berikut:
1. App startup (pertama buka hari itu)
2. After specific action (setelah save transaction ke-10, dll)
3. Scheduled (specific date/time)
4. Milestone reached (streak 7 hari, budget on track, dll)
5. Warning state (approaching limit, prediction defisit, dll)

### TASK 2.3: Display Rules Default

Sistem harus punya default rules yang WAJIB dipatuhi (kecuali di-override admin):

#### Global Rules

```
GLOBAL_RULES = {
  // Maksimum offer per hari per user
  max_offers_per_day: 1,
  
  // Waktu boleh tampil offer (jam)
  allowed_hours_start: 9,  // Pagi
  allowed_hours_end: 21,   // Malam
  
  // Skip weekend?
  skip_weekend: false,
  
  // Skip saat user dalam kondisi keuangan bahaya?
  skip_when_danger: true,  // Jangan jual saat user stress
  
  // Cooldown default antara offer
  default_cooldown_hours: 24,
  
  // Cooldown setelah dismiss
  cooldown_after_dismiss_days: 7,
  
  // Cooldown setelah "not interested"
  cooldown_after_not_interested_days: 30,
  
  // Max dismiss sebelum stop menampilkan
  max_dismiss_before_stop: 3,
  
  // First-time-today logic
  show_only_first_login_of_day: true,
  
  // Startup delay (biar user liat dashboard dulu)
  startup_delay_seconds: 3,
  
  // Auto-dismiss after (kalau user idle)
  auto_dismiss_after_seconds: 60,
  
  // Blocking (fullscreen) atau non-blocking (banner)
  default_display_mode: 'non_blocking'
}
```

#### Priority Order

Kalau ada multiple offer eligible, tampilkan berdasarkan prioritas:

1. **Critical Notice** (subscription expiring, payment issue)
2. **Feature Blocker** (user coba pakai fitur Pro+ tapi masih Basic)
3. **Milestone Celebration** (positive reinforcement)
4. **Contextual Offer** (relevant to current activity)
5. **Scheduled Offer** (campaign-based)
6. **Feature Discovery** (educational)

#### Display Format

**Format 1: Startup Modal**
- Muncul saat app startup (setelah 3 detik)
- Non-blocking, ada X untuk close
- Auto-dismiss setelah 60 detik idle
- Hanya 1x per hari

**Format 2: Persistent Banner**
- Muncul di dashboard sebagai banner
- Bisa dismiss (X)
- Untuk urgent action (subscription expiring, etc)

**Format 3: Contextual Sheet**
- Muncul bottom sheet saat user trigger tertentu
- Related to current action
- Slide up dari bottom

**Format 4: Inline Card**
- Muncul sebagai card di dashboard
- Non-intrusive
- Untuk feature discovery

**Format 5: Toast**
- Muncul sebagai toast notification
- Auto-dismiss 5 detik
- Untuk small offers/reminders

### TASK 4.4: Marketing Engine Logic

**Core Function: getEligibleOffers(userId)**

```
function getEligibleOffers(userId):
  1. Get user context:
     - Plan, subscription status
     - Household status
     - Feature usage
     - Financial status
     - Days since actions
     - Purchase history
     
  2. Get user preferences:
     - Marketing enabled?
     - Frequency preference
     - Quiet hours
     
  3. Check global rules:
     - Within allowed hours?
     - Under daily limit?
     - Not in critical state?
     
  4. Get all active offers
  
  5. For each offer:
     - Match audience filter?
     - Under max shows for user?
     - Past cooldown period?
     - Not dismissed too many times?
     - Match trigger context?
     
  6. Sort by priority
  
  7. Return highest priority eligible offer (or null)
```

**Core Function: handleAppStartup(userId)**

```
function handleAppStartup(userId):
  1. Check if first login today
     If not first: return
     
  2. Get eligible offer
     If none: return
     
  3. Wait startup delay (3 sec)
  
  4. Display offer in appropriate format
  
  5. Record 'shown' interaction
  
  6. Set up auto-dismiss timer
  
  7. Listen for user action
     - Click: navigate to offer target
     - Dismiss: record and hide
     - Not interested: record and add to blacklist
```

  - 'transaction_created_10th'

  - 'monthly_close_completed'
  
  1. Check if any offer matches this trigger
  2. Apply all standard eligibility checks
  3. Show as contextual sheet (not modal)
  4. Track outcome

## Poin-Poin Penting yang Perlu Diperhatikan

### 🎯 Prinsip Utama Sistem Ini

**1. Landing Page ≠ Aplikasi ≠ Marketing In-App**
Ketiganya harus **berbicara dengan suara yang sama**. Sistem ini memastikan setiap janji punya bukti, setiap fitur bisa di-monetize secara elegant, dan setiap user experience terjaga.

**2. Contextual Over Aggressive**
Offer muncul saat user butuh, bukan saat kita mau jual. Contoh:
- User coba tambah goal ke-2 → muncul offer Pro+ (contextual)
- Bukan: random spam upgrade offer setiap login

**3. Admin First-Class Citizen**
Semua strategi marketing bisa diubah tanpa deploy. Bisnis bisa iterate cepat.

### 🔑 Fitur Kunci yang Dibangun

1. **Family/Household Mode** — supaya Couple Pack punya makna
2. **Weekly AI Digest** — supaya Pro+ punya value nyata  
3. **Multiple Goals** — Pro+ differentiator
4. **Debt Payoff Planner** — Pro+ differentiator
5. **In-App Marketing Engine** — sistem cerdas untuk offer
6. **Super Admin Panel** — kontrol penuh untuk bisnis

### 💡 Yang Membedakan Sistem Ini

- **Respect user state**: Tidak jual saat user financially stressed
- **Frequency limits**: Max 1 offer per hari, cooldown after dismiss
- **First-login-of-day only**: Tidak spam berkali-kali sehari
- **User preferences**: Ada opsi off semua marketing
- **A/B testing**: Data-driven optimization
- **Feature flags**: Gradual rollout untuk minimize risk

Dengan sistem ini, Monefyi tidak hanya menyeimbangkan **janji dan bukti**, tapi juga membangun **relationship jangka panjang** dengan user melalui marketing yang membantu, bukan mengganggu.
